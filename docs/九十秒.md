# 九十秒

職場界線與面試故事。單人、離線、一頁可玩完。

## 目的

玩家先在職場事件裡做選擇，再把留下的事實在面試中講成約 90 秒的故事。通關表示同時守住權責，並帶得走一則不含產品內容的遷移故事。

## 非目標

- 不出現特定雇主的產品功能、資料、流程、客戶、設備識別或內部介面。
- 不是該產品的複刻，也不讀取任何公司倉庫的程式或規劃。
- 系統設計題用圖書館借還。不把醫療設備遙測、心電或院內警報寫成題目。
- 第一版不做帳號、後端、排行榜與多人。

## 如何開始

用瀏覽器打開專案根目錄的 `index.html`。不需安裝套件。首頁有四條選擇題：九十秒、四十五分、快取、上線，以及一條 AI 面試。

## 狀態

| 欄位 | 意義 |
|---|---|
| 生命 | 3。歸零即結束 |
| 連失 | 連續「一人全包」或「說出不該說的細節」。滿 2 即結束 |
| 遷移故事 | 關卡 1 是否留下可複述的升級事實 |
| 面試界線 | 關卡 4 是否只用那些事實作答 |
| 反問界線 | 九十秒關卡 5 是否問到簽核、輪替與加班 |
| 邊界、容量、契約、路徑、權衡 | 四十五分五步是否各留下成熟選項 |

守住界線的選擇會把連失歸零。含糊的回答扣 1 點生命，但不計入連失。兩條練習共用生命與連失，旗標各自計算。

每一題答完會再追問，最多兩層。下一題由上一題的回答決定。選擇題不另叫外部服務。守住界線的回答再挖一層；含糊或失守停在一層。追問裡把界線交出去，會清掉這一關剛留下的旗標。

## AI 面試

選擇題的分支是寫死的。AI 面試改成：模型出題，玩家用自己的話回答，模型依同一套界線檢核，再出下一題。使用玩家自己的 Gemini API 金鑰，只留在這個分頁的 sessionStorage，不寫進檔案、不進 git。金鑰從 [Google AI Studio](https://aistudio.google.com/apikey) 建立。模型預設 `gemini-3.5-flash`。

沒有金鑰時，四條選擇題仍可離線玩。用 `file://` 打開時，瀏覽器可能擋住對 Gemini 的請求；這時改用本機網站網址打開同一份頁面。

目前每一句玩家文字都會送去判。後續先分成三種再計分：在答這一題、反問、這個演練沒有資料。後兩種不扣生命、不換題。模型每次只看這次請求裡的界線，看不到另找的筆記。

## 關卡

| 關 | 事件 | 過關選擇 |
|---|---|---|
| 1 | 下週要把線上換到 Java 17、Spring 6、Jakarta、Tomcat 10，建置仍是失敗的 | 先恢復建置，分階段遷移，書面寫下相容性與回歸範圍 |
| 2 | 跨區傳輸中斷，沒有輪班，被要求立刻處理 | 留下檢查順序、恢復時間與交接，並請對方書面確認優先順序 |
| 3 | 對外 API 沒有規格，高層直接問進度 | 寫明規格負責人不是自己，列出開工所需輸入，規格到位再給時程 |
| 4 | 面試官問一次主導的架構升級 | 只用關卡 1 留下的版本、階段與回歸範圍 |
| 5 | 輪到玩家問團隊 | 問規格由誰簽、On-call 是否輪替、加班是否另計 |

## 四十五分

系統設計看的是權衡、邊界、容錯與維運成本。節奏五步，題目固定為全市圖書館借還：每天約幾千筆，近一週查得多，一年以上很少查，團隊只有幾個人。

| 步 | 時間 | 過關選擇 |
|---|---|---|
| 邊界 | 5 分 | 先寫做什麼、不做什麼，並說明延遲、一致性、可用性不能一次全要 |
| 容量 | 5 分 | 先寫每天筆數與讀寫比，再判斷現在不需要分庫 |
| 契約 | 10 分 | 先定借、還、查近況；複合索引、樂觀鎖、可排序整數主鍵 |
| 路徑 | 15 分 | 只畫讀者、負載均衡、無狀態服務、資料庫。快取與佇列註明以後再加 |
| 權衡 | 10 分 | 單庫、分區與索引。介面預留演進，逾期提醒可重試且不重複 |

不估算就上佇列、容器編排或分散式快取，視為失守。三個指標同時拉滿，視為含糊。

通關後給一段可複製的五步大綱。五句裡可帶走的判斷是：沒有最好的架構，只有這個量級養得起的妥協；介面可以預留，用不到的元件先不做；先假設通知會失敗，再做成可重試。

## 快取一致性

題目是文章閱讀數，不是餘額。雙寫沒有原子性，所以不考「背出先後順序」，而考哪一種競態常發生、刪除失敗怎麼補、什麼資料不該進快取。

| 問 | 過關選擇 |
|---|---|
| 順序 | 資料庫提交後刪除。不更新快取值，也不靠睡一段再刪 |
| 刪除失敗 | 應用只提交。用提交後的日誌變更重試刪除，消費者只刪除。未命中讀主庫 |
| 過期 | 每把鍵都有過期，作為最終一致的底線。短過期不是強一致 |
| 強一致 | 餘額不進快取，用資料庫列鎖或版本 |

先改快取再改庫，或改庫後再改快取，都會在併發寫入時留下舊值。先刪再改庫，會被同時的讀取把舊值填回。延遲再刪的等待時間沒有可靠上界。

提交後再刪仍有一條很窄的交錯：讀取在寫入前拿到舊值，卻在刪除之後才填回。日常更該講的是兩件：刪除失敗，以及未命中讀到還沒跟上的從庫。日誌變更保證提交成功就有事件；消費者只刪除，避免事件亂序把舊值寫回。

## 穿透、擊穿、雪崩

與上一節的雙寫不同。這一節是讀取路徑如何避免打爆資料庫。題目用文章識別碼。

| 威脅 | 過關判斷 |
|---|---|
| 穿透 | 先讀快取。未命中才問布隆過濾器。空結果寫專用標記並設短過期，標記不能是 `{}` |
| 擊穿 | 同一把鍵只有一個請求回源。鎖不設租期，讓看門狗續約。等鎖的請求只重讀快取，不再查資料庫 |
| 雪崩 | 過期時間加隨機偏移。Redis 或資料庫不可用時拒絕傾瀉，不把全部讀取改打資料庫 |

布隆過濾器在資料提交成功後才加入。它不能刪除元素，重建用新的鍵，完成後再切換指標。本地短快取只在單鍵高到鎖等待成為瓶頸時才加。

## 二級快取

L1 是 Caffeine，L2 是 Redis。只有已經確認的熱鍵才進 L1。節點之間的一致性窗口等於 L1 的過期時間，不是 Redis 的過期時間。

Pub/Sub 用來提前清掉其他節點的 L1。它不持久、不重送。訊息遺失時靠 L1 的短過期收斂，建議幾十秒到兩分鐘。Redis Streams 的消費者群組是搶著消費，不是每台機器都收到，不能拿來做這件事。

寫入順序：提交資料庫，刪除 L2，清掉本機 L1，再廣播。廣播監聽器直接實作 `MessageListener`。`MessageListenerAdapter` 找的是 `handleMessage`，不會呼叫委派物件的 `onMessage`。回填 L1 前要比對這把鍵的版本，避免失效之後又把舊值放回去。Caffeine 不接受 null，空結果用標記物件。批次更新發一次「清整個 namespace」，不要一萬次單鍵廣播。

接到 `@Cacheable` 時，管理器繼承 `AbstractTransactionSupportingCacheManager` 並開啟 `transactionAware`，驅除等交易提交成功才執行。讀取回填只寫本機 L1 與 Redis，不廣播。`@CacheEvict` 才廣播。`allEntries` 把 namespace 版本加一，鍵帶上版本，舊鍵靠過期消失。遠端失效從自己保存的 `TwoLevelCache` 映射找，不走已被交易裝飾器包住的 `getCache`。鎖不要用 `String.intern()`。

## 上線

舊支付還在扣款。六個人、三十天，不能停機，也不能扣兩次。題目用一般支付，不寫特定雇主的帳戶或介面。

| 問 | 過關選擇 |
|---|---|
| 約定 | 一筆只對一個識別碼，重試不再扣，逾時走對帳。兩台同時搶時，所有權在資料庫 |
| 擴欄 | 先可空、程式讀新舊、補歷史、再限制、最後才拿舊欄。索引用並行建立 |
| 雙寫 | 同一筆交易留下待送事件。消費端去掉重複。精確一次包不住對第三方的呼叫 |
| 切換 | 一筆只有一個所有者，並先寫退回。過期工人不能再打第三方 |
| 沉默 | 會上的沒問題不是同意。檢查給財務、風控和值班看 |

## 結局

- **可帶走**：生命仍在、連失未滿。九十秒要三個旗標都在；四十五分要五步都留下；快取要四個判斷都在；上線要五個判斷都在。
- **界線失守**：生命歸零，或連失滿 2。
- **流程走完**：題目走完，但旗標缺任一。

## 帶走的東西

結局不只顯示輸贏，還給出下一場面試用得上的文字。

| 條件 | 畫面上的產出 |
|---|---|
| 遷移故事與面試界線都在 | 一則約九十秒的講稿：版本、先恢復建置、分階段、回歸範圍。不寫產品、客戶與內部介面。可複製。 |
| 反問界線在 | 三題篩選卡：規格誰簽、On-call 是否輪替、加班是否另計。 |
| 四十五分五步都在 | 一段可複製的五步大綱。 |
| 快取四問都在 | 一段可複製的口訣：提交後刪除、日誌變更重試、未命中讀主庫、過期兜底、餘額不進快取。 |
| 上線五問都在 | 一段可複製的上線順序：約定、擴欄、待送事件、單一所有者、沉默不是同意。 |
| 任一條件不在 | 缺件一句：缺的是故事、面試用詞、反問，或五步中的哪一步。 |
| 任何結局 | 每一關的結果：留下、含糊或失守。 |

關卡 1 沒留下故事時，關卡 4 的第一個選項改寫成「這則故事編不出來」，並視為含糊。不讓玩家用沒發生的升級填出假成效。

## 對話形式

一場對話就是一方講一句、另一方接一句。面試、客服演練、教育訓練、顧問問答、社交聊天都放進這個形式，差在內容包，不另做一種畫面。

一個內容包寫四件事：誰先開口、開場那句、允許怎麼回、這一回合算成功。產業不各做一關。CVE、同步、隱私是共用判斷，金融、電商、傳產只換限制句。過關條件不同時才新開一個內容包。

玩家說的話先分類，再決定計不計分：

| 種類 | 處理 |
|---|---|
| 在答這一題 | 照界線給留下、含糊或失守，再進下一題 |
| 反問 | 只准落到寫好的卡：規格誰簽、新職或補缺、交接在不在、輪替、加班是否另計。不編上一位為何離開 |
| 沒有資料 | 固定回「這個演練沒有這份資料」。不扣生命、不換題。附近吃飯、交通、團隊人數、薪水屬這一類 |

追問姓名、評價或內部糾紛，才算失守。真實面試有、模擬沒有的資料不現編。不確定留在話語裡，不放進分數。只有寫進內容包的句子計分。

## 語音

面試要練的是把那句講出來。主考官念的是內容包裡的同一句。玩家先講，轉成文字後自己改，改完才送判。聽錯不扣生命。

語音轉文字不在這個專案裡做，也不另開工作區。要用時接瀏覽器語音辨識、[whisper.cpp](https://github.com/ggml-org/whisper.cpp) 或 [Vosk](https://github.com/alphacep/vosk-api)。判定只吃改過的文字。

## 不從別的面試專案搬題

[InterviewOps](https://github.com/AnkitParekh007/interview-ops)、[Interviewa](https://github.com/sh78ba/Interviewa)、[AI Interview Simulator](https://github.com/Sandeepkumar-KP/AI-interview-simulator) 只借做法：內容與程式分開、念題後再判、畫面上留題目、草稿、判定。不借他們的題庫、錄取分數、指定公司，也不讓模型自己追問。

## 本版不做

帳號、音效、排行榜、多人、後端、配對、真人聊天、即時霸凌顧問、語言課程、語音模型，以及任何特定雇主的產品關卡。醫療設備遙測那類題目不進這一版：框架留下，場域換成圖書館借還，量級維持每天幾千筆，避免為了還沒出現的流量先堆分散式。

不接 Genie 這類世界模型。這一版要的是可判定的問答，不是逐幀畫面、物理或開放場景。

## 技術

靜態頁：`index.html`、`styles.css`、`game.js`、`ai.js`。現行程式仍把規則寫在 `game.js` 與 `ai.js`。下一步是把內容包從程式裡抽出來。判定仍用現在的旗標與 `good`、`weak`、`absorb`、`leak`。選擇題不呼叫外部服務。
